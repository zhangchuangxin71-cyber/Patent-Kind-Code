# 新增专利对比实验详细报告

生成日期：2026-09-06（已补入 Yelp2018、Food 和 Amazon Beauty 的三方法对比）

本报告专门补齐两个原有证据缺口：（1）原始文本与 DeepSeek 优化文本的独立贡献；（2）LightGCN、原始 CausalDiffRec 与完整方法在统一协议下的比较。所有负结果与适用边界均保留，不根据 OOD 测试结果反向调参。

## 一、原始文本与 DeepSeek 优化文本对照

### 1. 实验要回答的问题

已有 real-vs-shuffled 实验只能证明“正确物品语义对应有用”，不能分离 DeepSeek 改写和 SBERT 编码的贡献。本实验直接比较：

- A 组：原始物品文本 -> 同一 SBERT -> 384 维 raw prior；
- B 组：原始物品文本 -> DeepSeek 规范化摘要 -> 同一 SBERT -> 384 维 LLM prior。

### 2. 保持不变与实际改变的因素

| 类别 | 具体设置 |
|---|---|
| 保持不变 | strict 数据划分、每个 seed 的同一冻结 checkpoint、全候选物品集、训练物品屏蔽、Top-20 评价函数 |
| 保持不变 | SBERT `sentence-transformers/all-MiniLM-L6-v2`、384 维、L2 归一化、100% 覆盖率 |
| 保持不变 | 用 train 交互的物品向量均值构造用户语义画像；协同分数和语义分数均按用户 z-score |
| 唯一有意改变 | SBERT 的输入是原始拼接文本，还是 DeepSeek 改写的规范化摘要 |

三组 prior 的物品数分别为 Food 6,309、Yelp2018 12,185、KuaiRec 10,612，两个文本来源的向量形状、SBERT 型号与 semantic mask 逐项一致。生成 raw prior 时写入独立文件 `semantic_prior_raw_sbert.pt`，没有覆盖原 LLM prior。

### 5. 一次性 OOD 结果

主分析将 LLM 选定的同一 alpha 同时用于两组，以最大程度隔离“文本来源”这一变量；辅助分析给两组相同的搜索范围，但各自使用自己在 validation 选定的 alpha。

| 数据集 | baseline | raw（共享 alpha） | raw（自选 alpha） | DeepSeek | DeepSeek-raw（共享） | DeepSeek-raw（各自选参） |
|---|---:|---:|---:|---:|---:|---:|
| Yelp2018 | 0.013448 | 0.013630 | 0.013530 | **0.014524** | **+0.000894** | **+0.000994** |
| Food | 0.027800 | 0.027946 | 0.027800 | 0.027684 | -0.000262 | -0.000116 |

Yelp2018 共享 alpha 主对比中，DeepSeek 相对 raw 提升 6.56%，5/5 种子胜出；配对差的描述性 95% t 区间为 [0.000403, 0.001385]，单侧精确符号检验 p=0.03125。

结论边界：Yelp2018 支持 DeepSeek 改写的独立正向贡献；Food 的 OOD 方向反转，必须作为负结果保留；KuaiRec 未通过 validation 门禁。不得写“DeepSeek 在所有数据集都更好”。

## 二、LightGCN、CausalDiffRec 与完整方法公平比较

### 1. 三种方法的准确定义

- LightGCN：仅使用协同交互图和 BPR 排序损失，不使用扩散、因果环境或语义。
- 原始 CausalDiffRec（E0）：VGAE + 扩散生成 + 原图编辑/环境建模 + 持久 LightGCN 排序头，不使用语义先验。
- 完整方法：因果扩散/LSCI backbone + `ConditionFusion` 语义条件 + `lambda_sem=0.1` 的 InfoNCE + 仅基于 train 交互的用户语义画像分数融合，`alpha=0.75`。

learned edge gate 在早期消融中未稳定超过 random gate，因此本次“完整方法”指已得到证据支持的可实施组合，`edge_gate_mode=none`；不把未得到支持的 learned gate 包装成已验证优势。

### 2. 统一的实验条件

| 条件 | 三种方法的共享设置 |
|---|---|
| 数据 | MovieLens-1M、Yelp2018、Food、Amazon Beauty 的 `v1_strict`，同一数据集内的 train/validation/OOD test |
| 候选集 | 全物品候选，屏蔽 train 已交互物品 |
| 评价 | Recall@20、NDCG@20，同一评价函数 |
| 选模型 | 只按 validation NDCG@20 保存 checkpoint；训练记录 `best_metrics=None` |
| 随机种子 | 1024、2048、3072、4096、5120 |
| BPR 预算 | 每种方法 25 次完整 BPR pass |
| 排序参数 | 8 维嵌入、3 层 LightGCN、batch=1024、lr=0.001、L2=0.001 |

每个数据集均完成 16 项直接公平性/无泄漏审计，全部为 true，`ood_test_allowed=True`。审计直接核验 validation-only 训练记录、相同数据版本/候选集/seed/预算/排序超参、checkpoint 存在性以及完整方法实际启用的语义条件、InfoNCE、固定 `alpha=0.75` 和关闭 edge gate。Yelp2018、Food、Amazon Beauty 未提供外部语义权重确认文件；因此 `alpha=0.75` 只能表述为该三方法组合的固定参数，不能表述为“已完成独立 validation confirmation”。“等预算”指排序学习的完整 BPR pass 数相同；CausalDiffRec 和完整方法仍执行各自架构所需的表示学习目标，这属于方法本身。

### 3. 冻结后的一次性 OOD 结果

| 方法 | Recall@20（均值±样本标准差） | NDCG@20（均值±样本标准差） |
|---|---:|---:|
| LightGCN | 0.028842 ± 0.000174 | 0.027902 ± 0.000020 |
| 原始 CausalDiffRec | 0.028596 ± 0.000163 | 0.027822 ± 0.000072 |
| 完整方法 | 0.037086 ± 0.000277 | 0.035068 ± 0.000094 |

完整方法相对原始 CausalDiffRec 的 NDCG@20 差为 +0.007246（+26.04%），正向种子 5/5；相对 LightGCN 的差为 +0.007166（+25.68%），正向种子 5/5。

专利中必须根据上表实际方向描述：可以声称的优势只限于配对差为正的对照；如果完整方法低于 LightGCN，则必须明确保留该结果，不得用不同训练预算的其他表替换。

### 3.1 在 Yelp2018、Food 和 Amazon Beauty 的同协议扩展

2026-09-06 将完全相同的 BPR25、超参、五种子、validation-only checkpoint 选模和冻结 OOD 测试协议扩展到 Yelp2018、Food 和 Amazon Beauty。三个数据集各自完成 16/16 项直接审计；每个臂各有 5 个 validation-only 记录和 5 个冻结 OOD 记录。三方法比较中的 `alpha=0.75` 为固定组合参数，未单独声称其经外部 validation confirmation 选出。

| 数据集 | 方法 | Recall@20（均值±样本标准差） | NDCG@20（均值±样本标准差） |
|---|---|---:|---:|
| Yelp2018 | LightGCN | 0.021620 ± 0.000343 | **0.016900 ± 0.000244** |
| Yelp2018 | 原始 CausalDiffRec | 0.016542 ± 0.000991 | 0.012828 ± 0.000742 |
| Yelp2018 | 完整方法 | 0.019540 ± 0.000336 | 0.015382 ± 0.000175 |
| Food | LightGCN | 0.047580 ± 0.000083 | 0.027838 ± 0.000144 |
| Food | 原始 CausalDiffRec | 0.049176 ± 0.000867 | 0.028374 ± 0.000305 |
| Food | 完整方法 | **0.049404 ± 0.000543** | **0.028656 ± 0.000163** |
| Amazon Beauty | LightGCN | **0.028586 ± 0.000558** | **0.012526 ± 0.000788** |
| Amazon Beauty | 原始 CausalDiffRec | 0.011694 ± 0.002249 | 0.004964 ± 0.001126 |
| Amazon Beauty | 完整方法 | 0.017484 ± 0.000812 | 0.007214 ± 0.000321 |

注：Yelp2018 与 Food 的上述 12 个标准差已于 2026-09-06 按 OOD 逐种子记录重新计算为**样本标准差**（`ddof=1`）。早期导出的 Word 表中这 12 个标准差错误，均值、配对差和方向不变；本 Markdown 表及对应 JSON 为修订后的唯一数值来源。

- Yelp2018：完整方法相对 CausalDiffRec 的 NDCG@20 为 `+0.002554` / `+19.91%`，5/5 种子正向，95% t 区间 `[0.001636, 0.003472]`，`p=0.03125`；但相对 LightGCN 为 `-0.001518` / `-8.98%`，0/5 种子正向。
- Food：完整方法相对 LightGCN 为 `+0.000818` / `+2.94%`，5/5 种子正向，95% t 区间 `[0.000499, 0.001137]`，`p=0.03125`；相对 CausalDiffRec 为 `+0.000282` / `+0.99%`，4/5 种子正向，区间 `[-0.000028, 0.000592]`，`p=0.18750`，不作为稳定优于 CausalDiffRec 的证据。
- Amazon Beauty：完整方法相对 CausalDiffRec 为 `+0.002250` / `+45.33%`，5/5 种子正向，95% t 区间 `[0.000784, 0.003716]`，`p=0.03125`；但相对 LightGCN 为 `-0.005312` / `-42.41%`，0/5 种子正向，`p=1`。

四个数据集的统一预算结论应严格按对照与数据集限定，并限定为本次五 seed、该数据划分和 BPR25 预算下的观察：MovieLens-1M 上相对两个对照均为正向；Yelp2018 与 Amazon Beauty 上相对 CausalDiffRec 为正向、相对 LightGCN 为负向；Food 上相对 LightGCN 为 5/5 正向、相对 CausalDiffRec 尚不确定。因此，不得写“完整方法在所有数据集均优于 LightGCN 和 CausalDiffRec”，也不得把 `p=0.03125` 概括为跨场景稳定优势。

该三方法表一次性改变了因果扩散/LSCI 训练结构、`ConditionFusion` 语义条件、InfoNCE 与最终用户语义分数融合。它只支持“该组合方法”的整体配对方向；不能把其中的增益单独归因于因果干预、InfoNCE、语义条件或最终分数融合中的任一模块。

### 4. 预算口径的额外说明

25-pass 表的目的是与 CausalDiffRec 原实验的 25 个 outer epochs 对齐，同时让每个 outer epoch 的排序头完整训练一遍。项目另有 MovieLens LightGCN BPR200 的较长预算曲线；不得把 BPR200 分数与本表 BPR25 分数并列宣称公平优势。

## 四、给专利撰写 AI 的结论边界

1. 可以把 Yelp2018 的 raw-vs-DeepSeek 结果作为大语言模型文本规范化的独立贡献实施例。
2. 必须同时说明 Food 方向不一致、KuaiRec 未通过门禁；不得概括为普适性提升。
3. 三方法表的“完整方法”已明确启用语义条件、InfoNCE 和分数融合，但不启用未获支持的 learned edge gate。
4. 四个 BPR25 数据集的方向不完全一致：本次五 seed 中，MovieLens 相对两个对照均为正向；Yelp 与 Amazon Beauty 仅相对 CausalDiffRec 为正向；Food 仅相对 LightGCN 为 5/5 正向。只能根据各对照的实际配对方向陈述优势，不得引用不同数据划分或不同预算的外部分数填表。

5. 专利技术主线应是“大模型规范化物品文本形成语义先验、训练期交互聚合用户语义画像、按用户标准化后融合语义与协同分数”；CausalDiffRec 比较作为一个实施例的对照，不得改写成跨数据集的唯一核心效果。
